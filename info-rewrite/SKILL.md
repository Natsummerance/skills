# Info Rewrite：工程化信息改写流水线

> 目标：把一段原文按指定规则改写成目标版本，且保证「可审计、指代不错乱、原话保真、敏感信息受控」。改写不是润色——不新增内容、不改事实，只在规则允许的范围内做替换与最小修顺。

## 核心原则

1. **规则先行**：动手前锁定改写规则（替换矩阵 / 目标对象 / 修顺边界），不临场瞎猜。
2. **脱敏贯穿**：改写前先脱敏；子智能体与所有中间产物只接触脱敏文本，交付前再恢复（过程脱敏 + 交付恢复）。
3. **双角色子代理**：有子代理环境时强制「改写执行 Agent + 独立审查 Agent」；没有则单线程双轮自审。
4. **保真优先**：保留原话结构与语气词，只做最小修顺；不改人名、地名、时间、数字、事件，不新增内容。
5. **交付可审计**：改写稿 + 逐条变更对照表 + 校验报告三件套；用户要求时导出 PDF。

## 工作流程（半交互）

### 第 1 步：锁定原文与改写规则
- 读取原文与用户的改写要求。若用户给了「替换矩阵/规则表」→ 原样固化并回读确认；否则问 1-3 个关键问题（改写目标、替换规则或映射、保真度要求）。
- 把固化后的规则写成本地文件（如 `rules.md`）供后续步骤引用。

### 第 2 步：脱敏（scripts/desensitize.py）
- 请用户提供要脱敏的人名清单（一行一个）；同时用内置正则识别手机号、证件号、座机、邮箱、微信号。
- 执行：
  `python scripts/desensitize.py mask -i 原文.txt -o 脱敏原文.txt -m 映射.json --names 名单.txt`
- 把「脱敏结果 + 映射规则」展示给用户确认（半交互确认点），确认后再进流水线。
- 之后所有子代理输入、中间产物、变更记录都基于脱敏文本；真实信息只存在于映射文件和最终交付步骤。

### 第 3 步：子代理 A——改写执行
- 派发子代理 A，提供：脱敏原文、固化规则、内置模板（如适用）、输出文件路径。
- 要求输出：`draft.txt`（改写稿）+ `changes.md`（逐条 原文片段→新文片段 + 原因分类：规则替换/语境消歧/最小修顺/删除）。
- 改写纪律：只做规则内替换与最小修顺；指代不明不许猜，写入「待主线程确认」。
- 无子代理环境：主线程按同样纪律执行，并在第 5 步强制做第二轮自审。

### 第 4 步：子代理 B——独立审查
- 派发子代理 B，提供：脱敏原文、draft、固化规则（不给 A 的结论与变更记录）。
- 检查项：漏改的规则词、指代错乱、称谓串线、原意走样、可读性。
- 输出：严重问题（必须改）/ 建议问题（可不改）/ 无问题段落清单。

### 第 5 步：主线程复核 + 机械校验（scripts/verify_rewrite.py）
- 先按 B 的严重问题修正，再对建议问题逐条裁定（保留或修正，记录理由）。
- 机械校验：
  `python scripts/verify_rewrite.py 脱敏原文.txt draft.txt --forbidden "你(?!们)" "我妈" "你妈" --count-allowed "你们:1" --report 校验报告.md`
- 用 humanizer 思路抽检口吻：最终稿仍应是「人话」，不做 AI 化润色、不新增内容。

### 第 6 步：恢复脱敏
- 用映射表恢复真实信息：
  `python scripts/desensitize.py restore -i draft.txt -m 映射.json -o 恢复后改写稿.txt`
- 恢复后通读一遍，确认占位符全部还原、无遗漏、无残留【】。

### 第 7 步：交付
- 交付三件套（Markdown）：改写稿、逐条变更对照表、校验报告。
- 用户要求 PDF 时：调用已装的 pdf skill（reportlab + Poppler 渲染校验）导出 A4 中文排版 PDF，内容只含正文。
- 汇报：改了多少处、哪些是语境判断、遗留建议。

## 内置模板：人称/称谓替换
- 见 `references/pronoun-rewrite-template.md`。适用于「把对 A 说的内容改成对 B 重述」这类任务，含替换矩阵、自指改判、轻顺稿边界、校验清单与示例。

## 降级模式
- 无子代理时：主线程先按第 3 步纪律改写，再以第 4 步视角独立自审一轮，自审差异写入对照表。

## 脚本说明
- `scripts/desensitize.py`：`mask`（打码）/ `restore`（恢复），人名走名单、其余走正则，往返一致。
- `scripts/verify_rewrite.py`：残留规则词扫描、词频统计、逐句 diff、报告生成，退出码 0=通过 / 1=不通过。
