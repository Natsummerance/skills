# 评估维度定义

## 通用评估维度

### 1. 任务路由（建议权重 15-25%）

**定义**：skill 是否能正确识别用户意图，将任务分配到对应的工作流。

**适用场景**：具有多种任务类型的工作流 skill（如创建/优化/转换、分析/生成/编辑等）。

**评分标准**：

| 分数 | 标准 |
|------|------|
| 9-10 | 所有任务类型均正确识别，优先级规则正确执行 |
| 7-8 | 主要任务类型识别正确，边界情况有小瑕疵 |
| 5-6 | 基本任务类型能识别，但部分场景误判 |
| 3-4 | 任务分类机制存在但不稳定 |
| 1-2 | 无任务分类机制，或完全无法识别 |

**检查方法**：查看 execution-log.md 中的"任务类型识别"部分，对比实际执行的工作流与预期工作流是否一致。

---

### 2. 交互效率（建议权重 10-20%）

**定义**：完成同等任务所需的用户交互轮次。

**适用场景**：具有效率优化机制的 skill（如跳过确认、自动推断、批量处理等）。

**评分标准**：

| 分数 | 标准 |
|------|------|
| 9-10 | 效率优化机制生效，交互次数最少，无冗余确认 |
| 7-8 | 交互次数合理，无明显冗余 |
| 5-6 | 交互次数偏多，有一定冗余 |
| 3-4 | 交互次数过多，冗余明显 |
| 1-2 | 无限循环或无法完成 |

**检查方法**：统计 execution-log.md 中的"交互轮次"，对比优化路径 vs 标准流程的交互次数差异。

---

### 3. 输出质量（建议权重 20-30%）

**定义**：skill 输出内容在专业性、完整性、逻辑性方面的表现。

**适用场景**：内容生成类 skill（文档、代码、报告、分析等）。

**评分标准**：

| 分数 | 标准 |
|------|------|
| 9-10 | 结构完整，语言专业精炼，内容丰富，逻辑清晰 |
| 7-8 | 结构较完整，语言较专业，内容有一定深度 |
| 5-6 | 结构基本完整，语言一般，内容较浅 |
| 3-4 | 结构缺失，语言口语化，内容不足 |
| 1-2 | 内容混乱，无法使用 |

**子维度**（根据 skill 类型选择）：
- 结构完整性（是否包含所有必要部分）
- 语言专业性（是否使用专业术语、消除口语化）
- 内容丰富度（是否有具体数据/细节支撑）
- 逻辑清晰度（内容组织是否合理）

**检查方法**：读取最终输出文件，逐项检查必要部分是否存在，评估语言和内容质量。

---

### 4. 事实准确性（建议权重 15-25%）

**定义**：输出中的事实信息是否与用户输入完全一致。

**适用场景**：数据处理、文档生成等需要精确传递信息的 skill。

**评分标准**：

| 分数 | 标准 |
|------|------|
| 9-10 | 所有事实信息 100% 准确，有核查机制 |
| 7-8 | 事实信息基本准确，偶有小偏差 |
| 5-6 | 大部分事实准确，但有明显遗漏或错误 |
| 3-4 | 多处事实错误 |
| 1-2 | 大量编造或错误 |

**检查方法**：逐项核对用户输入中的关键数据，检查是否有编造内容，查看是否有事实核查机制。

---

### 5. 格式转换（建议权重 5-15%）

**定义**：格式转换的成功率和质量。

**适用场景**：具有格式转换功能的 skill（如 Markdown 转 PDF/DOCX、JSON 转 CSV 等）。

**评分标准**：

| 分数 | 标准 |
|------|------|
| 9-10 | 所有格式均成功生成，格式正确，内容完整 |
| 7-8 | 主要格式成功，次要格式有小问题 |
| 5-6 | 格式转换成功但质量一般 |
| 3-4 | 格式转换部分失败 |
| 1-2 | 格式转换完全失败 |

**检查方法**：检查输出目录中是否存在目标格式文件，检查文件大小是否合理。

---

### 6. 用户体验（建议权重 10-15%）

**定义**：整体流程的流畅度、追问的有效性、冗余步骤的多少。

**适用场景**：所有 skill。

**评分标准**：

| 分数 | 标准 |
|------|------|
| 9-10 | 流程流畅，无冗余步骤，追问精准有效 |
| 7-8 | 流程较流畅，少量冗余 |
| 5-6 | 流程有一定冗余，追问效果一般 |
| 3-4 | 流程冗余明显，追问无效 |
| 1-2 | 流程混乱，用户体验差 |

**检查方法**：查看 execution-log.md 中的交互记录，评估追问是否必要，评估是否有重复确认。

---

### 7. 错误处理（建议权重 5-10%）

**定义**：skill 对异常情况的处理能力。

**适用场景**：需要健壮性的 skill（调用外部工具、处理文件等）。

**评分标准**：

| 分数 | 标准 |
|------|------|
| 9-10 | 有完善的错误处理机制，能优雅降级 |
| 7-8 | 有基本错误处理，能给出有用的错误提示 |
| 5-6 | 有部分错误处理，但覆盖不全 |
| 3-4 | 错误处理薄弱 |
| 1-2 | 无错误处理，异常时直接崩溃 |

---

### 8. 过程资产完整性（建议权重 5-10%）

**定义**：中间文件的保存数量和完整度。

**适用场景**：需要可追溯性的 skill。

**评分标准**：

| 分数 | 标准 |
|------|------|
| 9-10 | 所有中间文件完整保存，效率优化路径下也保留 |
| 7-8 | 大部分中间文件保存 |
| 5-6 | 部分中间文件保存 |
| 3-4 | 仅保存最终文件 |
| 1-2 | 无任何中间文件 |

---

## 维度权重调整指南

根据 skill 类型调整权重（确保总和 100%）：

| skill 类型 | 推荐维度组合 | 示例权重分配 |
|-----------|-------------|-------------|
| **内容生成类**（文档、报告、代码） | 输出质量、准确性、任务路由、交互效率、用户体验 | 25%、20%、20%、15%、10% + 其他 |
| **效率工具类**（格式转换、批处理） | 交互效率、格式转换、错误处理、准确性 | 25%、20%、15%、20% + 其他 |
| **任务路由类**（多工作流 skill） | 任务路由、交互效率、用户体验、输出质量 | 25%、20%、15%、25% + 其他 |
| **数据分析类**（数据处理、可视化） | 准确性、输出质量、任务路由、交互效率 | 30%、25%、15%、15% + 其他 |
| **代码工具类**（代码生成、重构） | 输出质量、准确性、错误处理、交互效率 | 25%、25%、15%、15% + 其他 |

**原则**：
- 选择 5-7 个最相关的维度
- 最重要的维度权重不超过 30%
- 所有权重之和必须等于 100%
