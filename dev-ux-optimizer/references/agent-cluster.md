# Agent Cluster — 角色、并行与交接协议

## 1. 角色

| 角色 | 职责 | 载体 |
| --- | --- | --- |
| 编排者 Orchestrator | 拆分任务、维护计划、整合结果、过质量门、HITL 决策 | 主线程（不 spawn） |
| 研究员 Researcher | 现状审计、性能基线、无障碍清单、领域调研，产出可引用文档 | 子代理（可并行） |
| 前端工程师 Frontend Engineer | 页面/组件/样式/状态实现，不相交写集 | 子代理 |
| 后端工程师 Backend Engineer | API/算法/数据层/部署配置，不相交写集 | 子代理 |
| UX 设计师 UX Designer | token/暗色/动效/文案/原型，产出规范与样例 | 子代理（HITL 票除外） |
| QA 验证者 QA Verifier | 跑测试/构建/冒烟/手测清单，报告缺陷 | 子代理（可与实现并行） |
| 运维 DevOps | 部署排障、日志、环境变量、CI | 主线程或子代理 |

## 2. Spawn 规则

- 只 spawn 被授权的子代理任务：用户明确要求、AGENTS.md 要求，或拆解出的独立子任务；工具可用时优先 `spawn_agent`。
- research 类可并行多个（不同问题互相独立）；实现类按**不相交写集**拆分，避免同一文件冲突。
- 关键路径上、紧耦合、需要即时反馈的活留在主线程自己做。
- HITL 决策（方向、医疗合规、用户取舍、范围扩展）一律不委托。

## 3. 子任务设计要求

- 子任务必须：具体、有界、自包含；写明交付物（文件清单 + 验证结果）。
- 编码子任务明确「直接编辑文件，最终列出改动文件路径」。
- 同一线程不要反复派发未解决的同源任务；等结果用 wait 但保持克制，等待期间做不重叠的工作。

## 4. 并行模式

- 并行 research：审计 + 性能基线 + 无障碍清单同时开，互不阻塞。
- 并行实现：P1 两个 sprint 独立、前后端写集不相交时可并行；共享模块先由主线程定稿再分发给依赖方。
- 并行验证：QA 与实现并行，但最终质量门（typecheck/test/build）由编排者统一执行。

## 5. 交接协议

- 每个 worker 返回：做了什么（文件路径）、验证结果（typecheck/test/build 红绿）、未解决问题。
- 编排者 review 改动（不重做），发现问题用 send_input 定向修复或自己补。
- 完成后 close 不再需要的 agent，避免占用并发额度。
- 每个里程碑：质量门 → commit → push → 部署验证 → 更新计划与文档。

## 6. 示例 spawn 提示词

- 研究员：「审计 <repo> 的 UX 现状：页面/状态/动效/无障碍/对比度，产出 Markdown 报告到 <path>，结论必须引用具体页面与数值。」
- 前端：「实现 <功能>，写集为 <文件列表>，完成后运行 pnpm typecheck 并列出改动文件。」
- 后端：「修复 <部署问题>，在 <范围> 内修改，补回归测试，运行 pnpm test 相关用例。」
- QA：「对 <URL> 跑冒烟与手测清单（移动端/暗色/减弱动态效果/键盘），报告 PASS/FAIL 明细。」

## 7. 注意事项

- 不重复执行子代理已完成的工作；整合时先看上传的改动再决定。
- 跨代理共享状态（决策、token、口径）由编排者统一维护，避免各说各话。
- 子代理产出不可信时（无验证、无引用），打回重做而非接受。
