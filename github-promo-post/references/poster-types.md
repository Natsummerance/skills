# 推文类型库 — 小红书 GitHub 项目推广（poster-types）

> 权威类型规范（2026-08-14 定稿）。所有 github-promo-post 推文必须从本库选型，
> 选型规则见文末映射表。定时任务（xhs_github_publish.py）只使用 T3/T4 模板化生成，
> 人工/触发语场景使用全类型。

## 通用铁律（任何类型都适用）

1. **标题 ≤20 字（含标点）**，前 8 字定生死：数字 / 痛点 / 反常识 / 好奇缺口 四选一。
2. **正文 600-700 字**，`1️⃣2️⃣3️⃣` 短行分段（替代加粗），每段 1-2 句，长短句错落。
3. **引导语必须「GitHub 搜 Natsummerance/xxx」**——用户名在前，禁止只写项目名。
4. 卡内/正文**禁止真实链接**（限流风险）；话题 5 个放末尾（`#GitHub #开源 #程序员 …`）。
5. 结尾必须**提问引导互动**（「评论区聊聊…」），结构化内容才有收藏率。
6. 数据/事实只能来自素材卡（references/projects.md）与真实 commit，禁止编造。
7. 配图遵循 references/poster-spec.md 范式，发布前过 validate_poster.py + 视觉复核。

## T1 痛点故事型（冷启动首推 / 大项目介绍）

**结构**：场景痛点钩子（3 个具体到能代入的画面）→ 转折「直到我换了 X」→ 亮点 3-5 点（1️⃣2️⃣3️⃣）→ 适合/不适合 → 引导+提问。

- **标题**：对比型「Typora 收费后，Windows 我换了这个」/ 反常识型「写 md 的人，最烦的不是写，是打开」
- **人味要点**：痛点要「具体瞬间」（表格缺分隔线、公式糊成一团、转 5 秒圈圈），不要抽象形容。
- **适用**：工具类大项目（readMD）首次发布、重新包装。

## T2 硬核测评型（框架/平台首推）

**结构**：一句话结论先行 → 背景问题 → 数字/对比（测试数、构建物、指标）→ 深度拆解 2-3 个核心机制 → 客观缺点 → 结论+引导。

- **标题**：数字型「650 个测试全过，这个框架把开会写进了代码」
- **人味要点**：结论先行给安全感；机制拆解用「它是怎么做到的」句式；缺点必须真实存在（没有缺点=广告）。
- **适用**：复杂框架类大项目（doAI）首次发布。

## T3 更新公告型（定时任务主力 · 大项目日常更新）

**结构**：一句话「X 更新了」+ 更新价值 → 更新点 3-5 条（1️⃣2️⃣3️⃣，从 commit message 提炼）→ 对新用户一句概要 / 对老用户一句「更新方式」→ 引导+提问。

- **标题**：「刚更新了！xxx 新增 N 个功能」/「xxx vX.X：修了三个让我抓狂的 bug」
- **人味要点**：更新点必须说「解决了什么」，不是复读 commit 标题；写「我自己最想要的是第 2 条」类主观句。
- **适用**：readMD/doAI 每次 push 后由定时任务自动生成。

## T4 单条安利型（定时任务主力 · skills/agents 小条目）

**结构**：一句话定义（这是什么）→ 解决什么问题（1 个场景）→ 怎么用（1-2 步）→ 亮点 2-3 条 → 引导+提问。

- **标题**：直给式「白嫖一个自动发布小红书的技能」/「这个 Agent 帮我省了 3 小时」
- **人味要点**：用「我」的视角说使用收益；单条篇幅可短（400-500 字），不硬凑。
- **适用**：skills 新增技能、agents 新增 Agent，每条目单独一篇。

## T5 盘点合集型（多条目批量新增）

**结构**：钩子（攒了一批）→ 清单逐条 1-2 句（1️⃣2️⃣3️⃣…）→ 按场景给选型建议 → 引导+提问。

- **标题**：「一口气放出 6 个 GitHub 工具，程序员自用」「这 4 个 Agent 一次打包给你」
- **人味要点**：清单每条要有「一句话人话」，禁止复制 README 摘要。
- **适用**：skills/agents 一次新增 ≥3 条目时。

## T6 教程实操型（功能上手引导）

**结构**：痛点 → 分步操作（step 1-5，每步一句）→ 避坑提示 → 结果展示 → 引导+提问。

- **标题**：「30 秒把 PDF 变成 Markdown，全程免费」/「三步让扫描件变成可复制文字」
- **人味要点**：步骤要「可照做」，避坑提示是收藏率密码。
- **适用**：readMD/doAI 单个功能的深度教程。

## 选型规则（需求 → 类型）

| 场景 | 类型 | 说明 |
|---|---|---|
| 大项目首次发布（readMD） | **T1** | 工具类痛点故事 |
| 大项目首次发布（doAI） | **T2** | 框架类硬核测评 |
| 大项目日常 push | **T3** | 定时任务自动生成 |
| 集合库新增 1 个条目 | **T4** | 定时任务自动生成 |
| 集合库批量新增 ≥3 | **T5** | 人工/触发语场景 |
| 功能教程 | **T6** | 人工/触发语场景 |
| 用户说「帮我把GitHub更新发小红书」 | 按更新内容选型：大项目→T3，条目→T4，批量→T5 | 触发语精修，走完整 LLM 创作 |

## 定时任务模板（T3/T4 自动生成规范）

- 标题模板：`「{仓库名} 更新了：{首条亮点}」`（≤20 字截断）
- 正文 = 概要段（素材卡「一句话定位」，让不了解的人看懂）+ 更新点列表（commit 提炼）+ 引导段
- 概要段每仓库固定文案（见 xhs_github_publish.py 内置素材），更新点动态拼接
- 字数控制：概要 ≤120 字 + 更新点每条 ≤60 字 + 引导 ≤80 字 ≈ 500-650 字
- 封面：单图 1080×1440 大字报（项目名+更新点），走范式校验
