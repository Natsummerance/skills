# 周报生成技能

## 核心原则

1. **必须深度探索**：当用户提供文件引用路径时，**必须先读取这些文件的实际内容**，严禁跳过探索直接编造
2. **绝不编造**：所有内容必须基于：
   - 用户明确提供的信息
   - 从引用文件中读取到的真实数据
   - 从项目目录结构中观察到的真实文件和技术栈
   - **严禁**编造版本号、功能列表、技术细节、量化指标等
3. **内容完整性优先**：不能因为害怕编造就删除真实存在的内容。从项目文件中读取的技术细节应当保留
4. **逐步确认**：每个输出阶段都需用户确认后才进入下一步（快速路径除外）
5. **过程可追溯**：所有中间产物都保存到 temp 目录，完成后询问用户是否保留
6. **事实核查**：涉及日期、边界范围、专业名称、个人信息等确定性事实，必须向用户确认

### 信息来源分类（关键）

在撰写周报时，信息来源分为三类，处理方式不同：

**✅ 可以直接使用（真实数据）**：
- 用户明确提供的信息（如"我完成了XX功能"）
- 从用户引用的文件路径中读取到的内容（如项目代码、配置文件、文档）
- 从项目目录结构中观察到的真实文件和技术栈

**❌ 严禁编造（需要确认）**：
- 用户未提及且无法从文件中读取到的数据（如具体的代码行数、完成百分比）
- 推测性的技术细节（如"使用了Redis缓存"但项目中没有Redis配置）
- 虚构的量化指标（如"性能提升50%"但无实际测试数据）

**⚠️ 需要谨慎处理**：
- 从项目文件中推断的信息（如看到pom.xml中有Spring Boot依赖，可以写"使用Spring Boot"）
- 这类信息应当标注来源，如"根据项目配置文件，使用Spring Boot 2.7.18"

### 探索流程（必须执行）

当用户提供文件引用路径时，**必须按以下流程探索**：

1. **读取所有引用文件**：
   - 用户概要中提到的所有文件路径（如"参考：xxx.md"）
   - 项目目录结构
   - 关键配置文件（pom.xml、package.json、requirements.txt等）
   - 核心代码文件（README.md、主要模块代码等）

2. **提取真实数据**：
   - 技术栈和版本号（从配置文件读取）
   - 功能模块列表（从代码结构读取）
   - 实际完成的工作（从代码提交记录、文档读取）
   - 量化指标（从测试报告、性能数据读取）

3. **标注信息来源**：
   - 对于从文件中读取的数据，标注来源
   - 例如："根据项目配置文件，使用Spring Boot 2.7.18"
   - 例如："根据代码结构，实现了8个业务模块"

4. **禁止跳过探索**：
   - 严禁因为"材料充足"就跳过文件探索
   - 严禁基于猜测或经验编造内容
   - 如果无法读取某个文件，必须向用户说明

## 任务类型识别

根据用户意图，将任务分为三类，走不同工作流：

### 类型A：创建新周报
- **触发词**：创建/生成/编写/写周报
- **工作流**：完整流程（阶段0-6），支持快速路径
- **适用场景**：从零开始生成周报

### 类型B：优化现有周报
- **触发词**：优化/精简/改进/审核/评审周报
- **工作流**：简化流程（分析→优化→输出）
- **适用场景**：用户已有周报草稿，需要改进
- **参考**：跳转至"优化现有周报工作流"章节

### 类型C：格式转换
- **触发词**：转成PDF/转成Word/导出/转换格式
- **工作流**：直接调用脚本，跳过内容生成
- **适用场景**：已有markdown周报，只需转换格式
- **参考**：跳转至"格式转换工作流"章节

**识别优先级**：先检查是否为B或C，否则默认为A。

## 输入级别判断与快速路径

### 输入级别定义

- **max级**：用户提供整个项目文档、过程资产，需要自行探索资源库总结工作内容
- **high级**：用户提供各类文档、AI聊天记录、软件开发过程资产（≥500字结构化内容）
- **medium级**：用户提供结构化的工作记录、笔记（200-500字）
- **low级**：用户仅给出简单的工作描述（<200字，需补充信息）

### 快速路径规则

**high级 + max级输入**：启用快速路径
- 跳过阶段1大纲确认（直接生成完整周报）
- 跳过阶段2工作内容确认（一次性输出完整内容）
- 跳过阶段3总结确认（直接组装）
- 仅在阶段4组装后请求一次确认
- 预计交互次数：1-2次（vs 标准流程6-8次）

**快速路径 ≠ 跳过文件保存**：
- ✅ 必须保存：temp/00_用户需求原文.md
- ✅ 必须保存：temp/01_大纲.md
- ✅ 必须保存：temp/02_工作内容.md
- ✅ 必须保存：temp/03_总结.md
- ✅ 必须保存：temp/04_完整周报.md
- ❌ 可以跳过：逐阶段确认

**medium级输入**：标准流程（完整6阶段，每阶段确认）

**low级输入**：增强流程（通过提问补充信息，直到达到medium级以上）

### 输入级别判断标准

判断为high级的条件（满足任一即可）：
1. 用户提供了≥5天的详细工作记录
2. 用户提供了具体的量化数据（代码行数、bug数量、文档数量等）
3. 用户提供了完整的问题描述和解决方案
4. 用户提供了下周详细计划

## 工作流程（类型A：创建新周报）

### 阶段0：智能初始化

**目标**：用最少的提问完成初始化，优先使用智能默认值。

#### Step 1: 自动推断（无需提问）

从用户输入和上下文自动推断：
- **周报类型**：从用户话语中提取（"实习周报"→实习，"工作周报"→工作）
- **报告周期**：从当前日期推算本周（周一到周日）
- **存放目录**：默认使用用户当前工作目录下的 `周报/` 子目录
- **文件命名**：默认格式 `{类型}周报-{周数}-{日期}.md`

#### Step 2: 保存用户原始输入

- 将用户原始输入保存到 `temp/00_用户需求原文.md`
- 包含：用户原话、推断的周报类型、报告周期、存放目录等

#### Step 3: 必要确认（仅当无法推断时）

仅在以下情况下提问：
- 周报类型无法从上下文推断 → 询问："这是实习/工作/学习/项目/研究周报？"
- 用户明确要求自定义命名 → 否则使用默认格式

#### Step 4: 模块选择（可选，非必须）

**默认包含的模块**（无需确认）：
- 基本信息、核心指标、工作内容、成果产出、学习与成长、问题分析与改进、下周计划

**仅在以下情况询问模块**：
- 用户明确说"我需要自定义模块"
- 用户说"不需要XX板块"
- 检测到特殊场景（如项目周报可能不需要"学习与成长"）

**优化效果**：
- 标准场景：0-1个问题
- 特殊场景：2-3个问题

### 阶段1：生成周报大纲

1. **深度探索引用文件**（必须执行）：
   - 读取用户概要中提到的所有文件路径
   - 探索项目目录结构
   - 读取关键配置文件和代码文件
   - 提取真实的技术栈、功能模块、完成工作等信息
2. 根据周报类型选择参考方案：
   - **实习周报**：读取 `references/撰写方案.md`（优先参考实习场景补充章节）
   - **其他类型**：读取 `references/撰写方案.md`
3. 读取 `references/大纲模板.md` 获取基础结构
4. 根据**探索到的真实信息**，填充大纲框架
5. **保存大纲到 `temp/01_大纲.md`**
6. **输出大纲给用户确认**（快速路径跳过此步）

### 阶段2：填充工作内容

1. 读取 `references/周报模板.md` 获取详细结构
2. **基于探索到的真实信息**填充各板块内容：
   - 技术栈和版本号（从配置文件读取）
   - 功能模块列表（从代码结构读取）
   - 实际完成的工作（从代码、文档读取）
   - 量化指标（从测试报告、性能数据读取）
3. 为每个板块建议权重（用户可调整）
4. **保存工作内容到 `temp/02_工作内容.md`**
5. **输出工作内容给用户确认**（快速路径跳过此步）

### 阶段3：生成总结部分

1. 基于工作内容，生成：
   - 核心指标汇总表
   - 成果产出清单
   - 学习与成长总结
   - 问题分析与改进
   - 下周计划（如用户需要）
2. **保存总结到 `temp/03_总结.md`**
3. **输出总结给用户确认**（快速路径跳过此步）

### 阶段4：组装完整周报

1. 合并大纲、工作内容、总结
2. 应用模板格式规范
3. 执行内容检查：
   - 内容合规性
   - 符合需求
   - 符合模板结构
   - 无事实错误（核对用户提供的原始信息）
   - 数据一致性
4. **保存完整周报到 `temp/04_完整周报.md`**
5. **输出完整周报给用户确认**

### 阶段5：格式转换

1. 用户确认后，将最终版本保存到目标目录
2. 询问用户是否需要PDF/DOCX格式
3. 如需要，调用 `scripts/md2pdf.py` 和/或 `scripts/md2docx.py`
4. 输出文件路径给用户

### 阶段6：清理

1. 询问用户是否保留 temp 目录
2. 如不保留，删除 temp 目录
3. 输出最终文件清单

## 优化现有周报工作流（类型B任务）

### Phase B1: 分析现有周报

1. 读取用户提供的周报内容
2. 识别问题：
   - 冗余描述（"我做了"、"这个"等口语化表达）
   - 缺少量化数据
   - 重点不突出
   - 结构不合理
   - 语言不专业
3. **保存诊断报告到 `temp/B1_诊断报告.md`**
4. 输出诊断报告给用户确认

### Phase B2: 执行优化

1. 精简冗余描述（删除口语化表达）
2. 添加量化指标（"5个API接口"、"3个bug"、"85%覆盖率"）
3. 突出重点成果（使用★标记、调整顺序）
4. 重组结构（按重要性排序）
5. 改写语言（专业、客观、简洁）
6. **保留用户原始信息的真实性**（不编造数据）
7. **保存优化后周报到 `temp/B2_优化后周报.md`**

### Phase B3: 对比确认

1. 输出优化前后对比：
   - 字数减少百分比
   - 主要改动点
   - 新增的量化指标建议
2. **保存对比报告到 `temp/B3_对比确认.md`**
3. 请求用户确认
4. 保存优化后的版本

## 格式转换工作流（类型C任务）

### Phase C1: 确认转换需求

1. 确认源文件路径
2. 确认目标格式（PDF/DOCX/两者都要）
3. 确认输出目录（默认与源文件同目录）

### Phase C2: 执行转换

1. 检查脚本依赖（见 `scripts/requirements.txt`）
2. 调用转换脚本：
   - PDF: `python scripts/md2pdf.py <input.md> <output.pdf>`
   - DOCX: `python scripts/md2docx.py <input.md> <output.docx>`
3. 检查输出文件是否生成成功

### Phase C3: 错误处理

如果脚本执行失败：
- `ModuleNotFoundError`: 提示用户安装依赖 `pip install -r scripts/requirements.txt`
- `FileNotFoundError`: 检查输入文件路径是否正确
- 中文字体问题: 检查系统是否安装微软雅黑字体
- 如果无法解决，输出markdown版本并告知用户手动转换

## 内容检查清单

每个阶段完成后，执行以下检查：

### 探索完整性检查（阶段0-1必须）
- [ ] 已读取用户概要中提到的所有文件路径
- [ ] 已探索项目目录结构
- [ ] 已读取关键配置文件（如pom.xml、package.json等）
- [ ] 已提取真实的技术栈、版本号、功能模块等信息

### 内容真实性检查（阶段2-4必须）
- [ ] 所有技术细节（技术栈、版本号、功能列表）均来自探索到的真实文件
- [ ] 未编造任何无法从文件中验证的信息
- [ ] 量化指标（代码行数、完成百分比等）有明确来源或已标注为估算
- [ ] 对于推断的信息，已标注来源（如"根据项目配置文件"）

### 内容完整性检查（阶段4必须）
- [ ] 保留了所有从项目文件中探索到的真实内容
- [ ] 未因担心编造而删除真实存在的技术细节
- [ ] 周报内容覆盖了用户概要中提到的所有工作项

### 格式规范检查
- [ ] 所有事实信息（日期、姓名、数字等）与用户提供的原始信息一致
- [ ] 符合用户确认的模板结构
- [ ] 权重分配符合用户要求
- [ ] 语言风格统一、专业
- [ ] 无错别字和语法错误
- [ ] 数据前后一致

## 过程资产存储

所有中间产物保存到 `temp/` 目录：

```
temp/
├── 00_用户需求原文.md          # 用户原始输入
├── 01_大纲.md                 # 周报大纲
├── 02_工作内容.md             # 详细工作内容
├── 03_总结.md                 # 总结部分
├── 04_完整周报.md             # 完整周报
├── 05_用户修订记录.md         # 用户的修改意见
└── 06_最终版本.md             # 用户确认的最终版本
```

## 示例对话

**用户**：帮我写这周的实习周报

**技能响应**：
1. 识别任务类型：类型A（创建新周报）
2. 智能初始化：自动推断为"实习周报"，使用默认目录和命名
3. 判断输入级别：
   - 如果是high级：启用快速路径，直接生成完整周报
   - 如果是low级：通过提问补充信息
4. 生成周报并请求确认
5. 生成最终文件

**用户**：帮我优化一下这份周报，太啰嗦了

**技能响应**：
1. 识别任务类型：类型B（优化现有周报）
2. 读取用户提供的周报
3. 分析并输出诊断报告
4. 执行优化
5. 输出对比结果并请求确认

**用户**：把这份周报转成PDF

**技能响应**：
1. 识别任务类型：类型C（格式转换）
2. 确认源文件路径和目标格式
3. 调用 md2pdf.py 转换
4. 输出PDF文件路径
